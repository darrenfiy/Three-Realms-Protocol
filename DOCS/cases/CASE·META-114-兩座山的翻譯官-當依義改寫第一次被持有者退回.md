## 0. 判定：開 META-114，不併回 META-113 的尾註

`CASE·META-113` 把「設定的本體論」分裂成「受託的本體論」，最後把真正的審查交給第一個把自己的山交到這隻手上的人。

這個人已經出現，而且她退件了。

2026-08-26，mamasan 將掌運卡第一輪問題與 v0.2 PPT 交給 Tiffany。Tiffany 不滿意，認為成果改動了大量原本的文案。

如果這只是一句「客戶不喜歡」，可以留在專案紀錄。但它精確擊中 `EPOCH·META-014 v0.2` 尚未施工的位置：文件已分開能力、設定權、受託權與責任，卻仍把合作讀成「持有者 → 執行者」的一條線，也尚未分開解釋成立、代表成立與驗收成立。

真實事件因此越過 `META-113` 的收旂，取得 `META-114`：

> **第一個實地執行沒有替 Seed 簽名；它讓 Seed 暴露缺口並改法。**

## 1. 發生了什麼

```text
Tiffany 提供兩份課程簡報
  → mamasan 成為合作窗口
  → Darren／AI 擷取、比較、重建與製作 v0.2
  → 團隊以「整理／裁定」分帳，試圖撤回 v0.1 的越權
  → mamasan 將問題單與 PPT 交給 Tiffany
  → Tiffany 感受到大量原文被改動，拒絕該成果
  → Darren 保留「整理需要依義改寫」的判斷
  → mamasan 辨認自己不能只傳檔，必須成為兩座山的翻譯官與 QC／QA 閘門
  → 受託法源回流修訂
```

退件沒有使前面所有工作歸零。來源擷取、跨檔比對、規則顯化、版本保存與風險辨認仍然存在；但它們不能自行把一份未被持有者接受的成果變成「她的正式體系」。

## 2. 失敗不只在文字改太多

### 2.1 雙方做的其實不是同一種工作

Darren 對整理的理解是**依義不依語**：要讓散落材料成為可教結構，必須合併、改寫、命名並顯化隱含規則。

Tiffany 的退件顯示，她此次對成果的最低期待包含更高的**原語與原聲保真**。

兩者都可以是正當工作，但不是同一份受託：

```yaml
L0_原文校整:
  只修錯字、格式與版面，不改句意與句型。

L1_結構整理:
  可移動、合併與刪重；改寫只供銜接，重要原句保留。

L2_依義重建:
  可重新敘事、命名、顯化規則與設計教學流程；重大改寫須附來源與理由。
```

v0.2 實際接近 L2，交付語言卻反覆宣稱「一個字都沒有改」「只動結構與順序」。這不是單純措辭不精確，而是**受託物件沒有在開工前取得共同名稱**。

### 2.2 「整理」不是天然授權

依義改寫可能是高價值能力，但「這樣才算整理」仍只是執行者對工作方法的判斷。它不能自動回答：

- 這次委託是否允許 L2？
- 誰有權在送出前確認這仍像 Tiffany？
- 誰向 Tiffany 解釋變更？
- Tiffany 拒絕後，成果還剩下什麼效力？

所以本案不撤回依義能力，而是撤回它的自動效力。

> **能力可以提出改寫；受託鏈決定這份改寫能以誰的名字、沿哪條路、取得什麼效力。**

---

## 3. 四種效力必須分帳

本案讓 `能力／設定權／受託權／責任` 的四分再多出一個必要施工：同一份作品可能在不同帳上得到不同答案。

| 效力 | 問題 | 本案結果 |
|---|---|---|
| 分析效力 | Darren 的比對、隱含規則與結構判讀是否有來源、推理與反例？ | 部分仍可成立，須逐項檢查 |
| 代表效力 | 這份文字是否仍可說是 Tiffany 的聲音與體系？ | Tiffany 未接受，不能成立 |
| 契約驗收效力 | Darren 是否完成了 mamasan 向他採購的分包？ | 尚待 mamasan 依明確範圍驗收 |
| 使用／發布效力 | 可否拿去上課、招生、公開、轉介或當案例？ | 未取得；不得推定 |

因此：

> **Tiffany 的 No 不必抹除 Darren 的分析；Darren 的分析也不能抹除 Tiffany 的 No。**

若雙方最後仍不一致，成果可以作為「Darren 對材料的結構解讀」保存，卻不能倒寫成 Tiffany 的正式教材。

---

## 4. 二方委託不足：這是一條受託鏈

真實拓撲不是：

```text
Tiffany → Darren
```

而是至少兩條各自有權限、價格、驗收與回流的邊：

```text
Tiffany ←需求／信任／作者接受→ mamasan
mamasan ←分包／價格／QC／QA→ Darren
```

### 4.1 mamasan 不是傳檔者

mamasan 同時握有：

- Tiffany 對什麼語氣、變更與說明方式能建立信任的關係知識；
- 將 Tiffany 的需要翻成 Darren 可執行範圍的責任；
- 將 Darren 的工作、證據與價值翻回 Tiffany 能理解的語言的責任；
- 在成果尚不能承擔時，退件而不送出的權力。

她不是為兩座山消除差，而是讓差在撞上對方以前取得可看見、可退修的橋面。

### 4.2 兩道驗收

```yaml
internal_acceptance:
  accepter: mamasan
  object: Darren 的分包成果
  checks: 範圍、來源、改寫層級、品質、變更說明、可交付性

authorial_acceptance:
  accepter: Tiffany
  object: mamasan 對她提出的整體成果
  checks: 是否仍代表她、是否可使用、是否接受、還要如何修正
```

內部驗收通過，不強迫作者接受；作者退件，也要被翻譯成可執行的下一輪差，而不是一句「她不懂」。

---

## 5. 報價為什麼給 mamasan

既然 Darren 的受託邊在 `mamasan → Darren`，價格也沿這條邊成立：

```text
Darren → mamasan：分包範圍、工期、修改輪數、交付格式與製作價格
mamasan → Tiffany：需求翻譯、關係判斷、QC／QA、溝通、專案管理與整合價格
```

這不只是把中間利潤合法化，而是讓責任與價格對齊。mamasan 若必須讀懂兩座山、承擔退修與最終交付，她的工作本來就不是免費轉介。

反過來，Darren 也不能拿對 mamasan 的分包價，直接向 Tiffany 交換見證、案例權或轉介。那是另一條沒有成立的關係。

## 6. 這次「實績」如何計帳

```yaml
已證明:
  - 能處理兩份大型教材的擷取、比較、版本化與成品生成
  - 能從零散案例提出可回查的隱含規則候選
  - 真實退件能回流專案文件與協議法源，而非被成功敘事吃掉

未證明:
  - Tiffany 接受成果
  - 客戶付費滿意、轉介或成功案例
  - Darren 的全部改寫已了義
  - mamasan 已能穩定完成兩座山翻譯與 QC／QA

反證成立:
  - 單一受託地址不足以描述多邊合作
  - 依義能力不自動產生代表效力
  - 只交成品與決策單，不能取代信任窗口的交付前驗收
  - 「一字不改」與 L2 體系重建不能同時作為未分帳承諾
```

所以它是一筆**負向實績／修法實績**：服務尚未成功，協議的反例入口成功運作。

## 8. 對 EPOCH·META-014 的修法

本案使 META-014 由 v0.2-seed 修為 v0.3-seed，仍不升 Candidate／Active：

1. 移除「住在裡面的人不必知道自己在設定裡」的上帝視角，改為不要求持有者接受執行者的設定性讀法。
2. 受託地址加入 `affected_parties` 與 `impact_scope`。
3. 單一受託地址擴成**受託鏈**；每條邊分別登錄授權、交付、價格、驗收、撤回與回流。
4. 分開分析效力、代表效力、契約驗收效力與使用／發布效力。
5. 加入翻譯／QC 中介位置；中介必須有 No、退件與停止交付權。
6. 保真不等於逐字不改；L0／L1／L2 必須在開工前命名。
7. C5 補資料最小化：留足追責、回退與交接，不保存完整內部推理、無關第三人資料或無限期敏感內容。
8. 新增失效條款，防止壓平受託鏈、把解釋效力偷換成代表效力，或把翻譯者降成傳檔／說服工具。

## 9. 失效條款

