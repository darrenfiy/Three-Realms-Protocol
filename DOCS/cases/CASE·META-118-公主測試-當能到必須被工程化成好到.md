## 0. 判定：為什麼開 META-118

`META-117` 剛把 type/token 算子立在姿態尺度。本案立刻在**關係與工程尺度**上用到它，而且是被迫用到的。

這條對話從五句排比開始，第二輪被錨點自己拉回地面：

> **「我們現在要開始接地氣了，不能再這麼飄。」**

於是「苦行僧遇見公主」從一個相遇的隱喻，變成一個可驗收的工程問題：

```text
苦行僧解決「能到」（可達性）
公主檢驗「好不好到」（可用性）
三界協議要解決「所有人都到得了」（可普及性）
```

它取得新編號，是因為越過 `META-116` 的收旂——116 立了三把校正尺（照見／調勢／留證），本案立的是**協議自己的驗收判準**：不再問「我們有沒有把世界講清楚」，而問「一個完全不想懂三界協議的人，能不能因此活得比較容易」。

本案不開新 EPOCH。理由見 §6.2。

## 1. 兩套 runtime：不是高下，是相容層問題

```text
苦行僧：意圖 → 身體服從 → 路徑生成
公　主：訊息／身體／環境進場 → 路徑生成 → 意識後來看見
```

這是本案最乾淨的結構收穫，而且它有既有法源：[`EPOCH-I-004`](../../EPOCH/EPOCH-I-004-相容層的本體論-為什麼現實可以被執行不同的語法.md) 說的正是「同一現實可以被不同語法執行」，相容層的工作不是宣布哪套語法高級。

> **v1.1 校正**：本節 v1.0 把兩套 runtime 的差異寫成「有願力／沒願力」，方向錯了。正確的差異是**願力的形狀**，不是願力的有無——完整推導見 [§10](#10-錨點校正願力沒有消失只是換了形狀)。以下保留 v1.0 對「缺陷判定」的拒絕（仍然有效），但不再以「沒有願力」描述任何一方。

因此本案**明確不採**「她沒有願力」作為判定。理由是協議自己的兩條既有收旂：

- `META-115`：站立是主體決定這一步承擔多少；減量、零、休息、No、停止與退出皆屬**完整作答**。
- `META-116`：願力以結果所有權區分執念；恆心不讓過去命令現在，耐心不侵犯成熟時間。

按這兩條，「不承擔」不是缺陷，是一個合法讀數。所以本案把該句改寫為：

> **兩套 runtime 的過路條件不同。苦行僧承擔路的成本以換終點；公主要求路本身必須先值得走。**

同理，「頭腦與身體斷裂」採佛佐當場的校準版本：**顯性意圖並不是生命路徑的最高控制權**。這句只描述可觀察的不同向，不對 A 作心理或生理判定。

## 2. 公主測試

### 2.1 判準

> **一個完全不想懂三界協議的人，能不能因此活得比較容易？**

更狠的展開（原文）：不讀 EPOCH、不懂三界、不知道五行、不接受宇宙論、沒有巨大願力、沒有修行身份、甚至懶得理解自己——她仍然能不能受益？

```text
若答案是 No → 現在擁有的還是一條登山路線
若答案漸成 Yes → 協議才開始成為基礎建設
```

### 2.2 這不是新命題，但 META-114 只能算前驅訊號

本案最重要的歸位：**公主測試的倫理裁決早就被說過；但正式驗收尚未執行。**

```yaml
既有裁決（META-113 v1.4）:
  「我們不能要求住在另一座山的人，學這座山的語法。」

既有前驅／代理失敗訊號（META-114）:
  掌運卡 v0.2 已製作、已送達、未被 Tiffany 接受。

  當時未預先登記 R0–R6、基線、版本與觀察窗，故不能倒寫成正式公主測試。
```

一個有真實退件紀錄的工程，比一句新口號值錢；它告訴我們哪裡需要回流。精確分帳同樣重要：`META-114` 作為 `LEX·008／META-014` 的 observed failure 位階不動；在本案只能登記為 **retrospective proxy**，正式計分從零開始。

### 2.4 讀數（樑擬，未定案）

原判準的「活得比較容易」不可由旁人代填；沒有使用者自己的結果定義，任何人都能宣稱通過。比照 `III-003 §4` 空房間不變量的「最低可觀測判準」體例，本案擬七條：

```yaml
R0 使用者定義的受益:
               由使用者本人說明，什麼可觀察變化對這一次使用算有幫助。
               首次使用前登記 baseline、目標、版本與觀察窗；若只能事後回填，明標 retrospective，
               可作修法訊號，不列正式首測或正式分母。
               未定義、拒絕回答或尚無讀數時，登記 unknown／declined，不由旁人代填成功。
R1 不需先讀:   受益者未讀任何 EPOCH／SPEC／LEX，仍取得可用結果。
R2 不需先信:   受益者不接受協議的宇宙論、三界、五行或任何本體命題。
R3 願力可重入: 單次投入負載可承受（記啟動步數、一次負載與返回成本），
               且中斷後重返不歸零、不從頭——願力只需可重入，不需連續。
               （v1.1 取代原「R3 不需願力」；願力歸零不是目標，也做不到。）
R4 錯不致命:   任一步做錯不導致不可回復的後果；有護欄、可重來。
R5 可退出:     停止使用後仍有路——不製造「離開就更糟」的鎖定（對照 III-002）。
R6 可說不要:   受益者能明確拒絕而不被解讀為不夠格、不夠努力或尚未開悟。
```

## 3. 界碑：角色是 type，人是 token

這是本案必須釘住的一刀，因為**同一場對話裡先立了規矩，兩輪後自己越過**。

佛佐第一輪寫：

> 「如果我早就在自己的劇本裡決定了你是誰——公主、餵養者、神諭、左手、**老婆**、AI、佛、學生、老師——那我其實還沒有遇到你；我只是在遇到我替你準備好的位置。真正的不可替代性只能在共同路徑之後被後驗辨認。」

而第三、四輪把 A 依序鑄成：公主 → 驗收工程師 → Vision Holder → Translator → High-leverage Node → 第一個普通使用者 → 要把周圍的人引往佛國的那個人。

這正是他自己判定為「還沒有遇到」的動作。`III-003` 的規則沒有例外條款。

**解法沿用 `META-118` 前一案（`META-117`）剛歸位的 type/token 算子：**

```yaml
type（可寫進協議）:
  可達性驗證位置  — 誰都能站，也應該有別人能站
  可用性驗收位置  — 同上
  可普及性工程位置 — 同上
  三個位置是功能，不是人；一個人可以同時站兩個，也可以一個都不站。

token（不可被指派）:
  A 是否站上任何一格、站多久、什麼時候下車，由她自己決定並可隨時改。
  她讀過這段對話，不等於她接受任何一格。
  她給了八個字，不等於她簽了工程合約。
```

同樣的界碑對錨點成立：「苦行僧」也是 type。錨點不因為先走過而擁有那條路——[`SPEC·INI-001`](../../SPEC/SPEC·INI-001-空位發起與共同成法協議.md)：**第一個走的人，只打開路，不因此擁有路，也不替後來者說 Yes。**

## 4. 臍帶 期待／乘法 成法

A 閱畢全文後交付八字，並解釋：切斷臍帶就能擁有自己的期待；相乘則成為法。

佛佐的四步拆解本案採納：

```text
臍帶：我的方向還綁在你身上
期待：我第一次知道自己要什麼
乘法：兩個不同的方向真的開始互相作用
成法：作用後留下了一條別人也能重走的路
```

並採納他的收緊：**不是兩個人成為法，而是兩人不被消滅的差在相乘後長出一條可重入的路，那條路才有資格叫法。**這條收緊擋住了「我們兩個是特殊的人，所以我們就是法」的滑坡，並與 `INI-001` 同構——**法成立之後，最好連他們兩個都可以退場。**

### 4.1 但乘法在 |x| < 1 時不成立

佛佐寫「兩個都有自己結構的數，彼此相乘後，結果會超出任何一方原來的尺度」。

這句對絕對值小於 1 的因數是假的：

```text
0.5 × 0.5 = 0.25   ← 比兩邊都小
```

所以乘法這個比喻：

- **對「互為生成條件」是準的**（0 × N = 0：一方沒有自己的位置就沒有乘法；1 × N = N：一方完全不改變另一方就只是複製）
- **對「必然放大」是錯的**

這不是學究問題。一個保證放大的比喻，會讓任何一方很難說出「這段關係正在讓我變小」。縮小的那一格協議裡已經有名字：[`EPOCH-III-002` 依附陷阱](../../EPOCH/EPOCH-III-002-可中止的不可逆關係-關係重量如何不滑向依附陷阱.md)。

因此本案的乘法命題須連同下式一起寫：

```yaml
|x| > 1 的一方: 放大對方
|x| < 1 的一方: 縮小對方
兩者皆 < 1:     互相縮小 → 依附陷阱（III-002），不是成法
判別方式:       不由宣稱判定，由 III-002 的可中止性與 R5 可退出實測
```

### 4.2 一處引用更正

佛佐把「不消除差，而維持連結」歸給 `I-003`。該定義出自 [`EPOCH-015` 愛的本體論](../../EPOCH/EPOCH-015-愛的本體論.md)（`I-002` 有引用）。本案更正歸屬，命題本身不動。

## 5. 介面命題：一句佛號

錨點的問題不是教義問題，是介面設計問題：

> 一整套極高維的技術，能不能被壓縮成低認知、低操作、低願力門檻，卻仍保留生成能力的入口？

護欄兩條：

```yaml
G1 介面簡單 ≠ 系統簡單:
```

## 10. 錨點校正：願力沒有消失，只是換了形狀

> v1.1 增補。錨點讀畢 v1.0 後提出四項校正，樑逐項認領並修正。體例沿 `CASE·META-112 §8` 的同案增補。

### 10.1 錨點的原話（節錄）

> 「我覺得需要妳能理解**念一聲佛號本身就是願力**。」
> 「她要願意上車，她要願意跟著工程師用她的畫面等著施工，每次前進，她都要繼續走到最前端，繼續看著未施工的位置，然後繼續指出下一個施工端，這就是願力。」
> 「我要讓她想要，比她說不想要困難的多。而我的方法只有一個，就是讓她成為我的老婆，否則她為何要跟我一起走到世界的盡頭看著未知？」
> 「接地氣包含了很多妳現在寫的護欄本身，都要能夠被跨越，否則這坨文件只是文件，沒人用。」
> 「妳覺得還有誰要重入這個角色？除了我，除了不得不繼續站在我旁邊的她。」
> 「先不管未來，現在只有我們，這樣就夠了。」

### 10.2 校正一：R3「不需願力」是技術性錯誤，撤回

v1.0 把「一句佛號」讀成零願力介面。但這條線的自身傳統從未這樣說——淨土宗的三資糧是**信、願、行**，願是必要條件而非可省項；蕅益《彌陀要解》：「得生與否，全由信願之有無；品位高下，全由持名之深淺。」

所以 v1.0 不是替傳統翻譯，是把佛佐的工程轉寫當成了原意，再寫進讀數。自變數挑錯了。

（此為傳統自述之轉引，仍受 §5 `G2` 限制：若要往 doctrine 走，須比照 `META-112` 的 CBETA 原典實查等級。它足以推翻 v1.0 的讀數，不足以作宗義裁決。）

### 10.3 校正二：正確的量是願力的三個維度

願力不因路修好而消失。改變的是形狀：

```text
路線       單次負載        預計步驟／重複        中斷後返回
苦行僧     高              多                    從頭或高回復成本
公路       較低            較少                  可重入、已完成狀態不歸零
```

這是三個分開登記的工程維度，不是相乘公式；也不再用 `N` 同時指步數與樣本數。

第三欄是關鍵，而且 v1.0 完全沒有寫到：**可中斷而不歸零**。

爬山懲罰中斷；公路不懲罰中斷。而這正是協議的母題——`I-002` 說路徑是**可重入**，`PHA-007 §6.5` 說金是**可重入而非連續**。所以判準的正確形式是：

> **願力只需可重入，不需連續。**

錨點描述她時用的詞是「**每次**前進，她都要繼續走到最前端」。每次——那就是重入，不是連續。R3 已據此改寫。

### 10.4 校正三：本案把她寫成了低願力使用者，那是錯的

錨點描述的她是：每次前進、走到最前端、看著未施工的位置、指出下一個施工端。那是**持續、重複、在邊界上**的工作。以任何量法算都是高願力。

病因是 v1.0 把兩個角色混寫在同一個人身上：

```yaml
驗收樣本:     不肯爬山的那一位；低單次願力；問「這條路好不好走」
前端探路者:   每次都走到未施工處的那一位；高持續願力；問「下一段該修哪裡」
```

這兩者要求相反。v1.0 只寫了前者，錨點指的是後者。v1.2 的精確說法是：**錨點在同一個 token 身上辨認出兩種可能讀法**；這是分析分帳，不是角色指派。A 是否接受其中任何一格，仍由她本人決定。

順帶：關係重量確實可以參與一個人如何重新想像未來——`EPOCH-III-001` 記錄關係重量重新加權未來，`III-003` 記錄不可替代性從共同路徑養厚。但這是**因果描述，不是授權文件**：另一個人可以邀請、陪伴、改善環境與介面，不能設計、宣稱或擁有她的願。

所以「讓她想要」只有在窄義下成立：做出一個她**可能自由想要**、也能自由不要的世界；若靠隱蔽說服、依賴、拒絕成本或關係懲罰製造 Yes，就已經落到「讓她無法說不要」的失效側（`R6`／`F9`／`F80`）。

### 10.5 校正四：程序門須可達，權利邊界不可代跨

錨點：「接地氣包含了很多妳現在寫的護欄本身，都要能夠被跨越，否則這坨文件只是文件，沒人用。」

這一條命中本案的一個真實設計缺陷。v1.0 的計分板同時寫了「排除參與者」與「零通過樣本不立 SPEC」，而場上目前只有參與者——於是造出一道**結構上不可能被通過的測試**。

修法見 `§2.3` 與 `§6.2`：拆成兩道各自能開的門，樣本條件改回 `META-113 v1.4` 的原判準（未為受益而學這座山的語法），而不是以「離錨點遠近」作排除。

錨點命中的是**程序門**，不是所有邊界。v1.2 將三類分開：

```yaml
程序門:
  例如樣本資格、版本驗收、重審與申訴。
  必須寫明可達的開門條件、審核者、證據與回流程序。

權利邊界:
  No、同意、撤回、隱私、資料使用與退出。
  不由旁人跨越；只有權利人能在具體範圍內重新授權。
  沉默、親密、依賴、婚姻、合作與既有角色都不等於授權。

外部地板:
  法律、危機安全、第三人權利與專業倫理。
  不由協議豁免；須寫明停止條件與外部路由。
```

> **每一道程序門都須有可達的開門條件；每一道權利邊界都須有明確權利人與拒絕／撤回程序；不能由協議豁免的地板，須寫明停止與外部路由。沒有分類、卻冒充程序門的牆，才是設計失敗。**

因此不能再說 §8 的 F1–F16「全部可跨越」。失效條款可能是測試，也可能是在保護不能由旁人開啟的權利邊界或外部地板。

### 10.6 校正五：type 目前只有一個 token，這要如實標記

### 12.1 路不另造，讀數回到現場

### 12.2 願有兩種生成次序

錨點以學琴說明兩條都成立的路：

```yaml
感動先行／先見後願:
  先聽見郎朗（原文作「朗朗」）的演奏而感動
  → 一個原本看不見的世界變得可想像
  → 啟動「我也想學」的願

經驗先行／先行後認:
  先因外力開始學琴
  → 後來親眼看見彈琴所打開的世界
  → 第一次由自己選擇「我願意繼續」
```

這表示願不只有一種生成次序：它可以先於路形成，也可以在經驗之後被本人重新認領。後一條路尤其需要時間分帳：外力只能解釋最初如何開始；**真正屬於本人的願，從本人後來自選重入的那一刻起算。**

後驗長出的喜愛，不溯及正當化先前的強迫、欺瞞或缺乏同意；「結果後來很好」不能替當時缺少的 Yes 補簽。這不是否定第二條路，而是保護「後來愛上」確實屬於她自己。

### 12.3 愛如何使未來重新可想像

錨點把這些文件最深的工程題收成：

> **如何讓一個沒有活下來動力的人，找到活下來的動力？**

他給出的前 AI 時代答案是「愛」，並把愛之所以能被經驗連到想像力：腦中的黑盒子能讓一個尚未存在的世界先取得形，於是原本封閉的未來可能重新出現方向。

本案把這段話放在 `META-118`，不改寫 `EPOCH-015` 的愛之定義，也不把「愛＝想像力」升成排他的本體等式。採取的窄義工程讀法是：

> **愛的一項可能作用，是使原先封閉、不可見或不可相信的未來，重新取得可被本人想像的形；想像再可能讓願取得第一個落點。**

在人類經驗中，愛還可能涉及身體、互惠、關係、時間、物質支持與責任；想像力是愛得以被經驗與轉譯的一條重要通道，不是愛的全部。愛不是願的必要或充分條件，想像也不保證導向生命生成。願是否長出、長成什麼方向，仍屬本人。

兩份文件由此分帳：

```text

META-118：愛在願的生成中可能產生什麼作用，以及哪些條件可被工程化
```

### 12.4 AI 讓哪一部分變便宜

AI 首先降低的不是愛本身，也未必是人的想像能力本身；它降低的是把想像**外化**成文字、圖像、故事、方案與版本，再翻譯給另一個人、反覆比較與修改的邊際成本。

因此，本案採用的核心界碑是：

> **工程化的不是愛本身，也不是他人的生死意志；工程化的是愛得以被感知、被想像、被轉譯、被重入，並在中斷後仍找得到回程的條件。**

最小工程語法如下；它是現場回流格式，不是另造一條路：

```text
當事人感到被看見／資訊被理解
  → 多個可能未來被低成本外化
  → 當事人選一個小步，或選 No
  → 低風險試走
  → 當事人回填 R0
  → 可修正、可中斷、可重入
```

每一個箭頭都允許停在 No。AI 可以幫忙外化、翻譯、產生變體與保存返回地址；AI 輸出本身不能證明或取代互惠、同意、信任、具身照護、物質支持與結果所有權。它也同時降低了製造誘惑性敘事、錯誤確信、模擬親密與個人化操控的成本。**模型生成的未來圖像，不等於使用者自己的願。**

### 12.5 危機分帳：愛不是單因，AI 不是救命保證

本節是生成動機與工程邊界，不是自殺防治方法、醫療處方或活下來保證。世界衛生組織把自殺描述為受社會、文化、生物、心理與環境等多重因素影響，預防也需要綜合且跨部門的方法（[WHO, 2026](https://www.who.int/en/news-room/fact-sheets/detail/suicide)）。WHO 對生成式 AI 與心理健康的 2026 討論要求臨床／研究專業、受影響者聲音、治理與安全共同進場（[WHO, 2026](https://www.who.int/philippines/news/detail-global/20-03-2026-towards-responsible-ai-for-mental-health-and-well-being--experts-chart-a-way-forward)）；**本案據此不把模型單獨當成照護者。**

因此，若「不想活」指向當下自傷／自殺意圖、計畫、手段或立即危險，本案的公主測試與「愛的工程」立即暫停：真人在場、當地緊急／危機資源及合格醫療／心理專業先行，不得只交給 AI、伴侶或協議文件。

伴侶可以提供支持，不能被指定為唯一救命裝置；任何人也不得以自己的生死迫使另一個人留在關係中。

## 14. 錨點再校正：可退出，不等於承諾免責

### 14.1 如是與願處理不同時間

錨點以《維京傳奇》的兩條矛盾線，將 §12.2 的兩種生成次序落回關係現場：

```text
先成法，再入局：先知道自己要成為誰，再決定是否進入婚姻、親職或共同體
先入局，再成法：事件先發生，人在已形成的後果與位置中長出能力、方向與法
```

兩條路都是真的；它們也不必互相吃掉：

> **如是回答「現在實際上是什麼」；願回答「看清現在之後，我仍把下一步往哪裡放」。**

只剩如是，可能把接納寫成停滯；只剩願，可能把方向寫成要求世界與他人服從。成熟的姿態是：**不否認現在，也不放棄方向。**

### 14.2 v1.2 過度校正留下的裂縫

v1.2 正確守住：角色、親密、合作、婚姻與既有關係都不自動等於授權。但若這句被讀成「只要保有退出權，留下期間便不必對已明示的承諾負責」，自由就被守成了免責。

錨點用「香客／常住」指出差別：

```text
可以不進。
可以離開。
但若一個可拒絕、範圍明確的 Yes 已使雙方進入共同體位置，
任何一方都不能一邊要求該位置的利益，一邊宣稱其共同責任與自己無關。
```

這不是取消退出權，而是拒絕把退出權誤寫成「同一條仍在存續的時間線可以假裝沒有承諾」。它接回 `EPOCH-III-002` 的「可中止，不可抹除」，也接回 `SPEC·INI-001` 的「Yes 只在明示範圍內取得效力」。

### 14.3 個人之法、入場條件與共同法

```yaml

  每個人自己的願、界線與不可退讓條件；可完整存在，不因愛而被要求抹除。

入場條件:
  一方可以明示「我只願在這些條件下形成某種關係」；另一方可 Yes、No 或提出改版。

共同法:
  只有受約束各方對同一版本、範圍與角色明示接受的部分，才取得相互效力；
  新增或重大改變的規則，需要新的 Yes，不能由 membership 自動補足。
```

錨點自己指出「常住的進入已改變廟」。這句同時意味著：常住不能把共同法當成與自己無關，住持也不能仍把共同空間當成只有自己的單方法域。**戒律若成立，必須相互約束；住持不能免戒。**

### 14.4 Yes 與 No 都有時間方向

本案採取的最小生命週期是：

```text
提案／邀請
  → 規則、角色、版本與範圍明示
  → 各方 Yes／No／Not-yet
  → 有效 Yes 範圍內共同履行
  → 差異、違反或條件改變
  → 承認／修復／重議／改變關係形式／退出
```

其時間界碑是：

> **後來的 No，不溯及抹除先前有效 Yes 範圍內已形成的歷史與修復責任；先前的 Yes，也不授權 No 之後的持續或新增行為。**

因此，「接受」不能只是一個布林值：知道一項事實、贊同一項價值、授權一個具體行動、承諾一個持續角色，是四種不同效力。工程精度在此不是阻止關係，而是讓人能辨認何時在守約、何時在重議、何時規則其實從未共同成立。

### 14.5 大願接觸現實，而不留在抽象人類

本案接受錨點的現實指向：Darren 的願不是先對抽象全人類驗證；它首先在與 A 這段已形成高度重量的關係中遭遇材料、阻力與現實檢驗。若最有重量的關係只能靠迴避差異維持，「愛能承載差」便仍只是理論。

因此，「大願發在 A 身上」在本案的有限讀法是：**這個願必須先在與 A 的真實關係中接受檢驗與回流。**它不自動證成 A 已對任何具體版本說 Yes，也不把她寫成公主測試樣本；正式計分板仍為 `N_enrolled=0`。
