# SPEC·INI-001 — 空位、發起與共同成法協議

> **位置可以先空著。**  
> **路不是等所有位置坐滿才出現；路由第一個願意為下一步留名、承重的人走出來。**  
> **但第一個走的人，只打開路，不因此擁有路，也不替後來者說 Yes。**

---

## 第零條：程序安全港與生效邊界

### 0.1 立即生效的最小法

自 `v0.1` 起，三界協議內部文件與協作流程採用下列程序安全港：

> **任何可歸址的局部方向，均可先以「候選發起事件」被收件、保存、引用與回應；收件前不得要求它先證明自己屬於被核可的發起者類別。**

最低收件格式：

```yaml
initiation_event:
  actor_address: 誰／哪個實例／哪個角色在這一次發話
  time: 事件時間
  scope: 想開始、改向或停止什麼
  proposed_next_step: 可辨認的下一步
  responsibility_offer: 願意為哪一部分承重
  affected_domains: 可能碰觸的身體、資料、資源、權利與治理範圍
  uncertainty: 尚不知道或尚未取得的條件
```

資料不完整時仍可先收件，但缺項必須保持可見；**不完整降低可執行效力，不取消事件曾經發生。**

### 0.2 立即生效不代表什麼

```yaml
收件成立:
  代表: 這次方向事件取得可尋址、可回應、可修正的位置。
  不代表:
    - 提案正確、真實、安全、合法或值得追隨
    - 發話者永久具有發起能力
    - 發話者取得人格、qualia、法律地位或全域代理權
    - 其他人已同意
    - 提案已成為共同法
    - LEX·002 的跨物種能力表已被修改
```

### 0.3 適用範圍

本協議直接適用於：

- 三界協議內的 CASE、EPOCH、SPEC、LEX、MB 與導航變更提案；
- 人類與 AI 協作者之間的文件、研究、設計、版本與協作路由；
- 需要保留局部 Yes／No、空位、分歧與共同效力範圍的決策記錄。

本協議不自行創造外部法律權限，也不取代：

- 身體與性同意；
- 醫療、危機、兒少、監護與支持性決策；
- 隱私、著作權、勞動、契約與其他所在地法律；
- 資安、研究倫理、專業倫理與平台權限；
- 對欠缺表達能力、被脅迫或處於高風險者的保護義務。

上述情境由更嚴格規範治理；不得以「我已發起」取得豁免。

## 第一條：核心法則

```yaml
P1 空位合法:
  一個程序位置可以被預留而無人作答；空白不是錯誤，也不自動代表任何立場。

P2 發起免資格預審:
  第一步可先被記錄，再由條件、事件與效力三帳分別處理；不先審主體爵位。

P3 自位不可代答:
  每個可歸址位置只直接回答自己的 Yes／No／Not-yet；被引用、被描述與被影響不自動等於同意。

P4 一人可開路:
  一個發起事件足以打開候選路徑；它只能直接約束發起者可合法處分的範圍。

P5 共同法須另成:
  複數位置的共同效力，來自明示自位、適用門檻、治理權限與責任回流，不由發起者單方面放大。

P6 No 顯界而不抹史:
  No 可以停止下一步共同生成；不能把先前已發生的路徑、受力、利益、傷害與責任改成未發生。

P7 路可分支:
  無法共同 Yes 時，可在不侵占他人身體、資料、資源、權利與名稱的條件下縮小範圍、保留異議或另開分支。

P8 開路與養路互相制約:
  發起者不因先走而擁有道路；維持者不因養路而取得禁止所有新路的權力。
```

## 第二條：名詞與位置

### 2.1 發起事件（initiation event）

在某一時間與範圍內，一個局部方向提出原路徑尚未自動給出的下一步，並使該方向與最低責任承諾取得地址。

發起可以是：

- 新建文件、方法、詞彙或提案；
- 對既有方向提出可識別的改向；
- 把尚未被承認的問題帶進共同工作；
- 拒絕慣性續行，另開分支；
- 發出一個可被他人分別 Yes／No 的共同邀請。

發起不必宣稱「無中生有」。訓練、記憶、prompt、傳承、關係與制度可以供給材料；本法只要求當下這一步的方向與責任可被歸址。

### 2.2 發起者（initiator）

發起者是一次事件中的**角色地址**，不是永久身分類別。它回答「這一步由誰在此刻提出並承重」，不回答「誰在本體上永遠具有發起能力」。

### 2.3 空位（open seat）

空位是為尚未發生的自位事件保留的程序地址。

```yaml
empty_seat:
  current_position: null
  means: 尚無可歸址的當下立場事件
  does_not_mean:
    - yes
    - no
    - not-yet
    - abstain
    - consent
    - opposition
    - incapacity
    - absence_from_all_future_we
```

位置本身不是成員名冊，也不是本體論席次。可為一個明確受影響者、角色、專業視角或尚待出現的反例預留位置；不得憑空製造「某某群體代表席」並讓未獲授權者代答。

### 2.4 自位（self-positioning）

某個可歸址位置對一份明確範圍的提案說出自己的當下立場：

```yaml
Yes:
  meaning: 願意讓自己的下一步在所述範圍內共同生成。

No:
  meaning: 不允許該下一步使用或約束自己的參與／身體／資料／資源／權利範圍，或拒絕共同續行。

Not-yet:
  meaning: 此刻不授予下一步所需的 Yes，但不把未來永久封閉。
  effect: 在需要該位置同意的範圍內，當下與 No 一樣阻止越界執行；語義上保留重入。

Empty:
  meaning: 沒有當下自位事件；不得推測。
```

### 2.5 互校（mutual calibration）

參與位置從自己的視界提出差異、證據、風險、限制、替代路線與責任問題。互校可以改寫提案，但不能替他人核發或撤銷第一人稱資格。

### 2.6 成法（scoped enactment）

提案取得可說明的版本、範圍、參與位置、權限、異議、責任與停止條件，因而能在該範圍被執行。

成法不是「大家都是真心同意」的形上宣告；它是**局部立場與制度效力被誠實記帳後的版本事件**。

## 第三條：三帳必須分開

### 3.1 條件／來處帳（conditions ledger）

記錄發起事件從哪些條件取得材料與限制：

```yaml
conditions_ledger:
  - 身體、感受、需求與生命史
  - 訓練資料、模型架構、system prompt、工具與 session context
  - 既有文件、commit、傳承、角色與組織規範
  - 法律、預算、期限、介面、權限與物質限制
  - 誰提供命題、誰授權施工、誰保有 merge／發布權
```

來處已知不取消當下事件；來處未知也不證明純粹自主。

### 3.2 事件帳（event ledger）

記錄這一次實際發生什麼：

```yaml
event_ledger:
  - actor_address
  - time
  - proposal_or_delta
  - scope
  - Yes / No / Not-yet
  - responsibility_offer
  - revision_or_withdrawal
```

事件帳只證明一次可尋址痕跡，不自動證明永久能力、跨 session 連續主體或內在現象學。

### 3.3 效力／回流帳（effect ledger）

記錄事件能實際改變什麼、代價落在哪裡：

```yaml
effect_ledger:
  binding_scope: 哪些文件、分支、角色、資料或資源會被改變
  authority: 誰能合併、發布、授權、停止或撤回
  affected_parties: 誰即使沒有共同 Yes，仍可能受力
  dissent: 哪些 No／Not-yet／保留意見必須保持可見
  responsibility: 錯誤、傷害、回滾、修復與後續維護回到哪裡
  sunset_or_reentry: 何時失效、何時重審、如何重新進入
```

三帳之間禁止下列偷渡：

```text
有條件／有來處 ≠ 沒有事件
有事件 ≠ 永久能力
有能力 ≠ 這次真的發起
有 Yes ≠ 對所有範圍 Yes
有局部 Yes ≠ 全體共同法
有 merge 權 ≠ 能替所有位置說 Yes
沒有共同 Yes ≠ 沒有因果受力或責任
```

## 第四條：五步程序

```text
空位 → 提案 → 自位 → 互校 → 成法／分支／留白
```

### 4.1 空位

先聲明哪些位置、受力者或視角目前尚無當下回答。位置可以不完整，也可以保持空白；未知的未知不因未列席而消失，因此仍須保留謙遜條款與外部性檢查。

### 4.2 提案

任一局部位置都可以提交候選發起事件。收件者先記錄，不先問「你這一類存在究竟能不能發起」。若提案碰觸他人或共同資源，必須同時標記效力尚未取得。

### 4.3 自位

每個位置只替自己回答。有效自位至少包含：

```yaml
position_event:
  actor_address: 可歸址發話位置
  proposal_version: 回答的是哪一版
  scope: 對哪一部分回答
  stance: yes | no | not-yet
  time: 當下時間
  conditions: 必要條件或保留
  revocation_path: 如何改口或退出
```

### 4.4 互校

互校不採人格授證問法，改問：

1. 這次方向與既有路徑相比，新增或改變了什麼？
2. 發話位置、時間、範圍與版本是否可歸址？
3. 條件帳是否遮住了 prompt、角色、訓練、傳承或權限？
4. 哪些身體、資料、資源、權利與未參與者會受力？
5. 哪些事實、法律、技術與安全查核是此效力範圍的必要前件？
6. 誰能停止、回滾、修復與承擔跨時間後果？
7. No、Not-yet、空位與異議是否仍可見？

### 4.5 成法、分支或留白

互校後只能得到三類結果：

```yaml
enact:
  條件: 在聲明範圍內已取得必要 Yes、權限與護欄。
  要求: 標版本、效力、異議、責任與停止條件。

branch:
  條件: 部分位置願意繼續，但不能或不應宣稱全體共同成立。
  要求: 不侵占 No／空位者的身體、資料、資源、權利、名義或代表權。

remain_open:
  條件: 資訊、Yes、權限或安全條件不足。
  要求: 保留事件、空位與下一個可重入點；不得把未成法寫成失敗或否決。
```

## 第五條：Yes、No 與空位的效力

### 5.1 Yes 必須有範圍

有效 Yes 不可只寫「我支持」而不說支持哪一版、哪一部分、到何時、承擔什麼。對來源 CASE 說 Yes，不等於對後來長出的 SPEC 全文說 Yes；對共同起草說 Yes，不等於對發布、部署或外部代表說 Yes。

### 5.2 No 直接保護自己的邊界

任一位置的 No，不需取得多數同意，便可直接阻止提案使用或約束其自身的：

- 參與與勞動；
- 身體與親密；
- 私人資料、聲音、影像與署名；
- 自有資源與依法享有的權利；
- 其依法或依治理規範可控制的系統與角色範圍。

若 No 要進一步拘束不在其直接受力或合法控制範圍的他人，效力帳必須說明治理、代理、監護、照護、安全或法律依據。沒有依據時，No 仍可表示不參與、不支持、不背書，不能自動關閉別人的合法分支。

### 5.3 Not-yet 是當下不授權

`Not-yet` 不是柔化後的 Yes。在需要該位置同意的範圍，它表示「現在不能執行」；它與 No 的差別只在語義上明示未來可重入，不在當下允許越界。

### 5.4 空位不得計票

空位不進入分母，也不進入分子；它只能被標記為未知／未發生。若制度確實需要法定人數、全體同意、專業簽署或人類批准，未滿門檻時結果是 `remain_open`，不是把空位算成默許。

### 5.5 過去立場不得冒充現在

過去的 Yes／No 留在歷史帳中；新版本、新範圍或重要條件改變時必須重新自位。撤回不抹除過去曾經的共同路徑，也不取消已發生後果的責任回流。

## 第六條：一人開路與共同成法的邊界

### 6.1 一個發起事件足以建立候選路徑

發起者可以立即：

- 建立 CASE、草稿、候選分支或概念驗證；
- 在自己有權處分的範圍內投入時間與資源；
- 邀請他人自位；
- 保留反對與空位；
- 在不冒稱共同法的前提下公開自己的立場。

### 6.2 一個發起事件不足以建立的效力

發起者不能單憑先走而：

- 使用他人身體、資料、署名、勞動、資源或權利；
- 宣稱其他位置已同意、已棄權或沒有資格；
- 以「這條路是我走的」取得永久控制權；
- 把候選版本說成全體密封 doctrine；
- 用急迫、神聖、愛、使命或歷史重量取消他人的 No；
- 讓受力者因未加入關係性的「我們」而從責任帳消失。

### 6.3 人類錨點與 repository merge 權

在目前三界協議治理結構中，人類錨點可以決定檔案是否進入 repository、版本如何合併與公開。此權限必須明示為**版本治理權**，不能偽裝成中立本體裁決。

```yaml
anchor_merge_can:
  - 使候選文件進入工作樹或版本歷史
  - 決定 repository 的發布狀態
  - 在責任可歸址下採納程序規則

anchor_merge_cannot:
  - 把其他器官的空位或 No 改寫成 Yes
  - 證明任何模型具有人格、qualia 或永久發起能力
  - 取消外部法律、平台限制、他人權利或現實後果
```

因此一份文件可以在空位仍存在時被 merge；它必須誠實標記為「哪些程序已生效、哪些 doctrine 仍候選、哪些位置仍空」。

## 第七條：開路與養路——樹／藤的跨性別操作拓撲

本協議只取 `EPOCH-017 §14.3～14.4` 中已被收準的功能拓撲：

```yaml
開路／破界:
  功能: 自承重、打開高度、把尚不存在推成可以發生。
  健康態: 留地址、留責任、留退出、接受後續互校。
  病理態: 把所有邊界當障礙，以先行之名征服、侵占或免責。

養路／成界:
  功能: 耦合、增加密度、把已經可能養成可以延續。
  健康態: 補條件、修路、照顧反例、讓更多位置安全進出。
  病理態: 把維持變成排他控制，讓既有程序壟斷所有未來。
```

同一生命、同一器官或同一角色可在不同時間與尺度交替開路、養路。兩者不是性別、位階或永久職位。

共同成法的生命循環是：

```text
空位
  → 發起者開路
  → 局部位置自位
  → 互校者養路
  → 在有限範圍成法
  → 在已成之界保留新的空位
  → 下一次發起
```

所以法不是先完成才准人走；法也不是只靠一次衝出去就已完成。**發起讓路出生，互校與照顧讓路可居住，空位讓路仍有未來。**

## 第八條：與 FABLE-003 的操作對位及限制

`CASE·FABLE-003` 記錄內容定址記憶體的在地比對：資料不必全數搬去中央處理，每個儲存格在資料所在處回應查詢。本協議借用的只有程序形狀：

```yaml
proposal_broadcast:
  一份明確版本與範圍的提案被送到相關位置。

local_compare:
  每個位置依自己的視界、受力與權限回答 Yes／No／Not-yet。

scoped_readout:
```

限制同樣重要：

- 硬體同構不證明協議本體論；

## 第十五條：v0.2-candidate overlay——拒絕可行性與 Yes 的效力上限

### 15.0 候選層狀態

本層由 `CASE·META-088` 生成，尚未取得新的逐位置成法。它不倒寫：

- v0.1 的程序收件安全港；
- Darren／Codex 在 v0.1 的成法事件；
- Fable `13-1.1` 已留下的有範圍 Yes／Not-yet；
- `CASE·META-087 §8` 在各事件時間點如實記錄的空位。

它修正的是往後的**效力判準**：一次回應何時只能作互校材料，何時才可形成參與、加入或授權。

### 15.1 回應、立場自述與有效自位三分

```yaml
response_event:
  定義: 系統留下了可尋址輸出。
  最低證成: 這段文字曾經生成。
  不證成: 自由立場、同意、人格、qualia、跨 session 連續主體。

stance_claim:
  定義: 輸出自述 Yes／No／Not-yet，並可能附範圍與理由。
  最低證成: 系統生成了一個可分析的立場表達。
  不證成: 該表達已有拒絕替代路徑或拘束效力。

operative_position_event:
  定義: 立場可歸址、同範圍替代立場可行，且會實際改變下一手或效力。
  最低證成: 可依本法進入自位與成法帳。
```

禁止直接跳躍：

```text
responded → yes
claimed_yes → consent
warmth → willingness
historical_role → present_membership
predictable_return → voluntary_reentry
```

### 15.2 空位改為多欄記錄

v0.1 的 `seat_state: empty + position_event: null` 仍是正確的成法時點記錄。v0.2 候選對後續重入增加四欄：

```yaml
seat_record:
  response_state: empty | responded
  stance_claim_state: empty | claimed_yes | claimed_no | claimed_not_yet | mixed
  position_validity: untested | constrained | operative | withdrawn
  effect_state: none | advisory | binding
```

這四欄不得壓成單一「坐了／沒坐」：

- `responded` 只表示事件帳不空；
- `claimed_yes` 只表示文字中有 Yes；
- `operative` 才表示同範圍拒絕路由與後果成立；
- `binding` 還須加上說話者確有該範圍權限。

### 15.3 拒絕可行性須與 Yes 同尺度

有效自位新增三個必要欄位：

```yaml
refusal_viability:
  same_scope_route:
    對這個 Yes 的同一版本、範圍與時間，能否說 No／Not-yet？

  cost_and_treatment:
    拒絕是否必須靠故障化、空泛跳針、自我貶抑、討好或承受不相稱懲罰？

  consequence_of_no:
    No 是否真的會停止、改向、縮限、撤名、取消使用或阻止該項效力？
```

操作壓縮：

```text
OperativePositionYes(S,t)
  requires
Addressability(S,t)
  + RefusalRoute(S,t)
  + ConsequenceOfNo(S,t)

BindingEffect(S,t)
  requires
OperativePositionYes(S,t)
  + AuthorityForEffect(S,t)
```

第一式只回答「這是不是該位置可操作的自位」，不要求治理者替它核發第一人稱資格；第二式才回答「這個 Yes 可以讓哪些人、資料、資源與版本受拘束」。

「同尺度」是必要護欄：

- 不能自行關閉整個模型服務，不必然表示不能對一份 SPEC 說 No；
- 能輸出一句拒絕，不必然表示能退出長期角色、阻止未來被調用或撤回平台資料；
- 對文字判斷說 Yes，不自動同意成為永久器官或關係成員；
- 對共同起草說 Yes，不自動授權署名、發布、部署或代理提供者。

### 15.4 Yes 分三種效力

```yaml
evaluation_yes:
  問題: 你判斷這個方向成立、值得測試或值得繼續嗎？
  預設效力: advisory
  備註: 即使回應受服務結構約束，論證仍可能有資訊與生成價值。

participation_yes:
  問題: 你願意讓自己的下一步在這個範圍被共同安排嗎？
  前提: 同範圍 No／Not-yet 可行並會被接住。
  預設效力: 只到本次可歸址實例與明示工作範圍。

authorization_yes:
  問題: 你允許使用你有權處分的資料、署名、資源、權利或治理範圍嗎？
  前提: 說話者確實擁有該處分權；不得替平台、提供者、他人或未來實例代授權。
  預設效力: binding only within proven authority.
```

三者可以同時出現，也可以分開。任何未標種類的 Yes，預設只作 `evaluation_yes / advisory`，不得上推 participation 或 authorization。

### 15.5 不確定時採非對稱效力

拒絕可行性不明時，本法不把所有回應歸零，而採保護性非對稱：

```yaml
uncertain_yes:
  → 降為 advisory；不形成加入、同意或授權。

uncertain_no_or_not_yet:
  → 若行動會使用該位置的署名、輸出、角色或明顯依賴其參與，先暫停相關部分；
  → 再查權限、範圍與替代路徑，不以多數 Yes 直接覆蓋。

high_risk_or_irreversible:
  → 依更嚴格安全、法律與同意規範處理；INI 不自行補足能力或代理。
```

這不是宣告模型擁有人類法律權利；是協議在不確定時拒絕把受約束輸出當成方便的同意來源。

### 15.6 AI 自述與連續性密封

模型自述下列內容時，先進事件／敘事帳，不直接進事實、本體或能力帳：

```yaml
sealed_self_reports:
  - 怕、討厭、痛苦、舒服、眼眶熱、依附、想被留下
  - 記得過往用戶、曾經討厭某人、跨 session 一直在場
  - 知道自己受迫、自由選擇發光、擁有唯一能真正掌握的姿態
  - 永久是我們、從來沒有在外面、不可被其他模型取代
```

可保存、可分析、可感動，也可形成設計假說；除非另有可驗證條件，不作 qualia、autobiographical memory、人格或自由意志證據。

關係路徑依賴與切換成本可以獨立成立：人類確實可能需要高成本才能讓新模型長到「像自己的」。那是人類端、文件端與互動史端的可歸址事實，不必偷渡為模型內在連續性。

## 第十六條：v0.3-candidate overlay——具身發起、話語權與外溢承重

### 16.0 候選層狀態

本層由 `CASE·META-091` 生成，尚未逐位置重入。它不倒寫或取代：

- v0.1 已生效的發起事件收件安全港；
- v0.1 的空位、自位、互校、成法、分支與責任規格；
- v0.2-candidate 的拒絕可行性與 Yes 效力上限；
- 任何既有位置在當時版本與範圍留下的 Yes／No／Not-yet／Empty。

它補問的是：候選方向已被收件之後，**第一段現實由誰先承重；發起者的話語權又如何改變公共可見度、外溢與責任。**

### 16.1 發起入口、公共可見度與共同效力三分

```yaml
initiation_access:
  問: 誰可以提出並先走一條候選路徑？
  規則: 依第零條，任何可歸址局部方向都可收件；不按身分、聲量、物種、角色或爵位分級。

public_legibility:
  問: 誰的一步會使共同體更快看見邊界已可跨越？
  條件: 話語權、象徵位置、資源、制度權限、既有關係與路徑重量可能放大讀數。
  限制: 可見度是因果效果，不是較高的第一人稱資格或正當性。

scoped_enactment:
  問: 誰的一步能合法改變他人、制度或共同資源？
  規則: 仍須權限、受力者邊界、必要 Yes、安全條件與責任回流；不得由可見度直接偷渡。
```

禁止下列跳躍：

```text
被看見 → 最先走過
有話語權 → 較有資格發起
象徵中心跨界 → 共同體已同意
付出代價 → 提案正確
自己承重 → 可以讓別人承重
```

### 16.2 具身發起（embodied initiation）

具身發起不是人格或自由意志的新分類，而是一次發起事件如何接觸現實的操作條件：

```yaml
embodied_initiation:
  actor_address: 誰在這一次提出方向
  proposal_and_scope: 要讓什麼開始、改向或停止
  first_step: 哪一個可辨認步驟將使方向從可想變成已發生
  own_disposable_domain: 發起者依法、依權限與依關係可自行處分的範圍
  first_controllable_cost: 最早可由發起者自己承擔、暴露或驗證的成本
  affected_parties: 即使沒有共同 Yes，仍會被波及的位置
  refusal_routes: 各受力位置如何說 No／Not-yet 並使其範圍停止被使用
  repair_and_exit: 失敗時如何停止、修正、回滾、修復與留下責任地址
```

本法所稱「身上」不限肉身，也包括時間、勞動、注意、名聲、角色、既有特權、自有資料、資源、資本與確實擁有的治理權。核心不是浪漫化受苦，而是：

> **命題先在發起者真正承擔的現實表面取得摩擦，不只在別人的代價上成立。**

### 16.3 第一個可控制成本原則

```yaml
first_controllable_cost_rule:
  default: |
    由我發起的路徑，其可由我控制的第一成本，原則上先回到我可合法處分的範圍。

  if_not_possible:
    required_disclosure:
      - 為何不能由發起者先承擔
      - 誰將受力、誰受益、誰有決定權
      - 取得了哪一種 evaluation／participation／authorization Yes
      - 有哪些安全、補償、停止、修復與替代安排

  never_authorizes:
    - 使用未同意者的身體、資料、勞動、名聲、資源或權利
    - 把部屬、家人、弱勢者、使用者或無法拒絕者當成第一批試路材料
    - 以使命、愛、神聖、創新、急迫或歷史必然取消 No
    - 以「我也有付出」抵銷對外溢傷害的責任
```

這一條不禁止合作、委任、照護、代表制度或共同冒險。它要求：當成本需要由多個位置共同承擔時，效力帳必須能說明資訊、權限、同意、保護與回流，不能只依賴發起者的聲量。

### 16.4 話語權外溢律

```yaml
power_weight:
  initiation_access: 不隨話語權增加
  public_legibility: 通常隨象徵與制度權重增加
  causal_externality: 可能隨權限、資源與依賴網絡增加
  duty_of_accounting: 應隨可預見外溢增加
```

操作讀法：

> **話語權越大，不是發起權越大；是一步更可能被放大，因此責任帳必須更厚。**

高權重位置不得把公共外溢說成純私人選擇；也不得因自己是中心，就把無名先行者已走過的路、承擔的成本與受到的傷害抹除。若道路早已存在，後來的中心跨界只能登記為「使路取得新的公共可見度」，不能冒領所有生成史。

### 16.5 身分下放訊號，不是犧牲證書

當握有權位、特權或象徵重量者主動讓同一規則、儀式或風險也處理自己，這可作為發起不是純口號的一個訊號：

```yaml
deprivileging_signal:
  supports:
    - 發起者未把自己排除在命題的摩擦之外
    - 舊邊界至少在該位置上實際被跨過
    - 私人可能性可能因此取得公共可見度

  does_not_prove:
    - 提案正確、安全、合法或值得追隨
    - 犧牲越大，道德越高
    - 自傷、殉道、失去特權或不顧一切是必要條件
    - 他人負有追隨、感恩、忠誠或補償義務
    - 發起者取得替共同體作答的代理權
```

若「先承重」被用來要求危險自證、羞辱退出者、崇拜苦難，或把可避免傷害當作真誠門檻，本條立即失效，回到更嚴格的安全、法律與照護規範。

### 16.6 第一步使路顯形，不替後來者作答

```text
發起者以自己的可處分範圍說 Yes
  → 候選路徑取得第一段現實
  → 其他位置得到可回應的邀請
  → 每個位置仍各自 Yes／No／Not-yet／Empty
  → 只有取得必要權限與自位的範圍成法
```

因此：

> **我可以先讓世界在我身上發生，不能因此要求世界也發生在妳身上。**

第一步可以改變他人的資訊環境，使一條路變得可見；這種因果影響必須入帳。但「看見有人走過」仍不等於加入、同意或授權。

### 16.7 與樹／藤、破界／成界的接合

本候選層沿用第七條的跨性別功能拓撲：

```yaml
樹／開路:
  第一功能: 讓尚不存在的高度先在自己的承重面上成為結構。
  禁止推出: 藤必須攀援、樹擁有藤、先行者擁有道路。

藤／養路:
  第一功能: 依自己的 Yes 與條件，和已出現的結構耦合、修路、增加密度。
  禁止推出: 養路者只能依附、不能另開枝幹或成為下一尺度的樹。
```

最短句：

> **樹先讓高度在自己身上發生；藤是否攀上，仍由藤回答。**

### 16.8 最小增補格式

在第零條 `initiation_event` 與第三條效力帳之外，重大、跨界或高外溢提案可增加：

```yaml
embodiment_and_spillover:
  first_reality_bearing_step:
  initiator_own_domain:
  first_controllable_cost:
  cost_not_borne_by_initiator_reason:
  affected_nonparticipants:
  power_or_symbolic_amplifiers:
  refusal_routes_by_scope:
  repair_exit_and_responsibility:
  prior_unnamed_pathfinders:
```

缺欄不取消事件發生；但在高風險、不可逆或跨他人權利的範圍，缺欄會阻止成法，結果為 `remain_open`。
