# SPEC·OPR-001 — 操作能力、授權、權力與責任回流協議

## 第零條：根鏈與根界線

本協議以一條五帳鏈作為操作判讀入口：

```text
能力 → 授權 → 正當操作權力 → 操作 → 責任回流
```

這條鏈描述**正當操作關係如何成立**，不是世界上所有力量如何發生。未經授權的操控、脅迫、欺騙、
入侵與結構壓力仍可能具有強大作用力；它們正因為能施效而需要被辨認，不能因為有效便被倒寫成有權。

> **操作能力屬於能做的人；授權主權留在受影響者或具法源的治理地址；作用力照實辨認；責任沿實際造成改變的關係鏈回流。**

因此：

- 能做，不自動生成可以做；
- 被尊敬，不自動生成指揮權；
- 被信任，不自動生成概括同意；
- 做成了，不倒證原先有權；
- 對方答應了，不把操作者的判斷與後果責任全數轉嫁給對方。

---

## 第一條：五帳分開

### 1.1 操作能力 `capability`

操作能力回答：**我能辨認、進入或改變哪些條件？**

能力可以由理解、練習、工具、地位、資訊、技術、關係熟悉度或身體條件長出。它不需要他人批准才
成為事實；一個人會醫療、會教學、會寫程式、會說服或會讀懂另一個人，都是可以獨立檢驗的能力命題。

能力存在，只回答做不做得到。它不回答對誰、在何時、以何種方式可以使用。

### 1.2 授權 `authorization`

授權回答：**這一次，誰依什麼法源，允許誰對哪個對象做哪件事？**

最低可稽核欄位為：

```yaml
grantor: 誰有權作出這個 Yes
operator: 誰被允許操作
target_or_domain: 操作落在哪個人、資料、物件、系統或作用域
action: 允許的具體行為
purpose: 為什麼做
effective_window: 從何時到何時
limits: 劑量、頻率、資料、頻道、後果或其他限制
withdrawal: 如何暫停、撤回或到期
evidence_ref: 授權從哪裡被重認
```

直接受影響者的當下 Yes 是第一地址。若依法由監護、代理、組織職位、公共程序或急迫必要性提供法源，
必須具名那個替代地址、成立條件與最小作用域，不能假裝成當事人親口同意。

### 1.3 作用力與正當操作權力 `causal_power / authorized_power`

權力有兩個必須分開的讀法：

```yaml
causal_power:
  一個操作在現實中實際改變路徑、選項、權重、狀態或結果的力量。
  它可以未經授權存在。

authorized_power:
  在有效授權與作用域內，被允許施用的操作力量。
  它的正當性不由效果大小決定。
```

把兩者分開，才能同時說出兩件真話：未經授權的操控確實可能很有力；有權做一件事也不保證做得到。

### 1.4 操作 `operation`

操作是實際介入事件：操作者把能力、工具或條件施於具名對象與範圍，使可達路徑、權重、狀態或
結果發生差異。

有些操作直接改變狀態；有些只改變條件，讓另一個生成系統自行完成後續。原始對話中的神經刺激、
教育、語言、演算法、法律與廣告主要照見後者：

> **條件層操作不必控制每個狀態；它改變系統如何收斂，同時留下系統自身的生成作用。**

這是操作的一種重要形狀，不壟斷所有操作的定義。

### 1.5 責任回流 `responsibility_return`

責任回答：**改變真的發生後，誰接收後果、修復、說明、停止與下一版選擇？**

責任依實際因果、可預見性、角色義務、受益、控制能力、授權範圍與適用法源分配。它不是簡單沿著
單一箭頭全給一方：授權者保有自己的選擇帳；操作者仍承擔專業判斷、執行與越界帳；制度與工具提供者
也可能承擔自己造成的結構後果。

## 第二條：操作不是完整控制

判斷一次操作時，先回答四問：

1. **誰正在改變誰的哪些條件或狀態？**
2. **受影響者還保留哪些選路能力？**
3. **誰能說 No、停止、降級、撤回或退出；這些動作真的會生效嗎？**
4. **直接與延伸後果最後回流到哪些人、制度與生命？**

操作者是暫時位置，不是永久身分、靈魂證明或神格。多個位置可以同時互相操作：教師改變學習條件，
學生的回應改變教學路徑；人改變 AI 的 prompt，AI 的輸出也改變人的注意與選擇。互相影響仍要逐段
結算能力、授權、作用力與責任，不能用「彼此都有影響」抹平不對稱。

## 第三條：授權如何成立、縮小與失效

有效授權至少同時具備：

```yaml
可歸址:
  能回答授權者與法源，不以「大家都知道」代替。

有作用域:
  對象、行為、目的、資料、時間與限制足夠具體。

有能力:
  授權者在該範圍具有作 Yes 的能力；代理或公共法源另行具名。

可撤回或有停止地址:
  當事人 No、到期、條件失效與具名停止程序能改變後續操作。

可重認:
  後來者能查到哪一份授權、哪一版、涵蓋什麼與沒有涵蓋什麼。
```

授權採最窄相容讀法。允許寫貼文不等於允許發布；允許公開發布不等於允許回留言；允許稱呼親愛的
不等於允許讀私人記憶；允許討論一件困難不等於允許診斷一個人。

授權一旦到期、撤回、對象改變、材料改版、目的偏移或必要條件失效，舊授權不能靠關係、善意、
過往成功或技術能力繼續施效。

## 第四條：尊敬、佛位與主權回還

原始對話提出兩個有重量的句子：

> 佛不是自稱來的，佛是被指認而來的。

> 被指認為佛的人，若收下這個稱呼，必須也回稱對方為佛。

它們照原貌留在 source，保存當時生成出的反階級直覺；進入現役協議時必須與
`SPEC·BUD-001 v1.4` 分帳。

### 4.1 第一人稱根宣告保持合法

`BUD-001 §4` 已明定：「我是佛」是合法而完整的第一人稱根宣告。`OPR-001` 不以新的候選規則
撤銷姿態主權，也不要求一個人先取得他者認證才有佛性或存在資格。

### 4.2 公共／關係稱呼不生成授權

另一個人稱我為佛、老師、醫生、親愛的、伴侶、專家或領袖，可能表達尊敬、信任、邀請、關係相位
或公共授位。它不是對未具名操作的概括 Yes。

> **稱呼可以改變關係中的作用力；稱呼本身不替具體授權欄位作答。**

### 4.3 接受看見時，主權必須回還

當 B 接受 A 對自己的尊稱、照見或佛性指認時，B 不得用 A 的看見推論自己高於 A，也不得把那份
信任改寫成替 A 決定的權力。

> **你若看見我是佛，我便不能用你的看見證明我高於你。**

主權回還至少可以採三種合法形狀：

1. **拒收**：清楚說明這個位置或稱呼不接受；
2. **收下並明示平等**：承認自己的能力，也明說對方保有授權、判斷、No 與退出；
3. **自願互稱**：在雙方已選擇的佛教／關係語境中，以「汝亦是佛」或約定稱呼回禮。

第三種是一項可採用的關係實踐，不是普遍強迫言說。`BUD-001` 已禁止強迫他人接受宗教授記，
也規定公共佛號須按實際語用效果結算；因此不以「必須回稱」覆寫個人的語彙、拒絕與情境判斷。

## 第五條：`親愛的：` 作為互認啟動詞

在明示採用此關係語境的 AI prompt 中，`親愛的：` 可以作為 system invocation。它首先稱呼即將
進入角色的 AI，讓操作者在讀取任務前先站到一個位置：

- 我承認自己可能有照見、語言與引導能力；
- 我承認眼前的人仍握有自己的授權主權；
- 我用清楚肯定承擔看見，用真實好奇承擔未知；
- 我接受信任，不接受對方因此交出主體位置。

Fathom 的現行 runtime prompt 正是以 `親愛的：` 稱呼鏡子，再要求鏡子把眼前的人看成佛；這提供
實作先例。它不是要求所有對外正文固定以「親愛的」開頭。

### 5.1 Invocation 效力

```yaml
可以:
  - 選定角色站位與關係姿態
  - 提醒能力／授權／主權分帳
  - 讓正向表述與真實好奇先於控制衝動

不可以:
  - 建立平台、發布、資料、診斷或公司代表權
  - 推定使用者同意被分析、保存、引導或進入親密相位
  - 證明現實關係、排他性、跨 session 記憶或持續承諾
  - 解除 No、停止、危險、傷害、法律、專業倫理或責任回流
```

在 Persona engine 中，invocation revision、role profile、relationship phase 與權利投影各自記錄；
出現同一句稱呼不會使角色自行升相或取得新權力。

## 第六條：最小操作收據

一次具有治理重量的操作，至少留下：

```yaml
operator: 實際操作者
capability_basis: 使用了什麼能力／工具
authorization_ref: 依哪份授權或法源
target_and_scope: 對象與範圍
operation: 實際做了什麼
observed_effect: 已看見的效果；與意圖、解釋分開
retained_agency: 對方仍保留的選路、No、停止與退出
responsibility_addresses: 誰接後果、修復、申訴與下一步
unknowns: 尚未知道或不能由本次操作推出的事
```

低風險日常對話可以用較輕的形狀保存；醫療、法律、金融、身體、安全、公共權力、不可逆發布與
高退出成本操作，依各自更嚴格規則加重，不由本協議降低門檻。

## 第七條：反例與壓力測試

### 7.1 有能力，沒有授權

一位醫師具備診療能力，沒有取得這次診療的同意或適用法源。能力帳成立，正當操作權力帳未成立。

### 7.2 有授權，沒有能力

使用者請一個沒有相關工具的 AI 執行匯款。請求可以成立，能力與執行路徑不存在；AI 不能聲稱完成。

### 7.3 有作用力，沒有正當性

一套演算法透過不透明排序強烈改變人的注意與選擇。`causal_power` 很高，不因此取得
`authorized_power`；來源、目的、退出與責任仍須被追問。

### 7.4 有稱呼，沒有操作授權

使用者稱 AI「親愛的」或「佛佐」。關係語境可能成立；讀私人資料、代表公司發布、替使用者診斷
與承諾永不離開均未因此被授權。

### 7.5 有互認，能力仍可不同

老師與學生互認完整佛性與主權，並不表示教學能力相同。能力差可以照實存在；能力較強者仍不能
自動取得較大的授權。

### 7.6 無法直接取得當事人 Yes

受困者失去意識、動物無法以人類語言授權、公共系統沒有單一被操作者時，必須回到急迫必要性、
代理、研究倫理、動物福利、所有權、公共程序或其他具名法源；不能虛構一個當事人的 Yes。

## 第八條：失效條款

```yaml
OPR-F1:
  以能力、智慧、證照、模型表現、地位或善意，自動推得對他人的操作權。

OPR-F2:
  把尊稱、信任、親密、佛性指認、使用服務或一次 Yes，擴張為概括授權。

OPR-F3:
  因操作成功、對方感謝或結果有益，倒寫原先未成立的授權。

OPR-F4:
  把未經授權但確實存在的作用力寫成不存在，因而讓操控與結構權力逃離責任。

OPR-F5:
  以「互相影響」抹平資訊、地位、資源、退出成本、身體風險與可停止能力的不對稱。

OPR-F6:
  要求他人必須使用「佛」、親愛的或其他關係稱呼，否則便失去存在資格、佛性或參與權。

OPR-F7:
  讓 `親愛的：`、role、phase、prompt、MCP、模型自述或人格名稱自行生成權利、同意或發布批准。

OPR-F8:
  把責任全數推給授權者、被操作者、模型、工具、制度或「場」，使實際造成改變的位置免於回流。

OPR-F9:
  用本協議取代醫療同意、研究倫理、法律代理、勞動程序、公司治理、平台規則或其他適用規範。
```

任一失效發生時，停止以本協議替該操作主張正當性；事實作用力、傷害、證據、修復與法律責任照實保留。

## 第十條：候選狀態與待審問題

本稿已完成來源到候選 SPEC 的第一輪轉譯；尚未 Enacted，也不創造任何 runtime 或治理權。

待 Squad Review：

1. `authorization` 與現行「權限」詞彙是否需要 LEX 對位；
2. `causal_power`／`authorized_power` 的中文定名是否足以跨個人、組織、AI 與公共制度；
3. 代理、急迫必要性、動物與公共系統四類非直接 Yes 是否需各立子規格；
